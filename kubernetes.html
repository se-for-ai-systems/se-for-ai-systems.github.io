Kubernetes Cluster Guide

How to access and use the course Kubernetes cluster

Before Seminar 1: install kubectl and Helm, add your kubeconfig file, and check that you can connect (steps 1–3 below).

What You Get

  • Access to a shared course Kubernetes cluster, run by the course staff. You only need the kubectl and helm clients on your own machine.
  • Your own namespace (one per student or group). No services are shared between students or groups: you deploy and operate everything yourself (your model service, MLflow, event broker, monitoring, ...).
  • A personal kubeconfig file, sent to you by email. It contains your access token – do not share it or commit it to Git.

Your Permissions

Scope Access
Your own namespace Full access to all resource types: get, list, watch, create, update, patch, delete.
The rest of the cluster Read-only: get, list, watch (e.g. kubectl get nodes).
  • Your kubeconfig sets your namespace as the default, so you do not need -n <namespace> for your own resources.
  • You cannot create cluster-wide resources such as namespaces, ClusterRoles or CustomResourceDefinitions. Tools that require a cluster-wide installation (e.g. operators) can therefore not be installed by you – choose namespace-scoped alternatives.
  • Over the network, your pods can reach services in your own namespace, but not services in other namespaces.
  • No ingress or egress: nothing in the cluster can be exposed to the outside world, and your pods cannot reach the internet. Use kubectl port-forward to reach your services from your laptop. Ingress resources and NodePort/LoadBalancer services will not make your application reachable.
  • Container images: the cluster pulls images from public registries such as Docker Hub or GitHub Container Registry. Push your own images to a public registry and deploy them from there.
  • Deployment: you deploy from your laptop with kubectl and helm. GitOps operators such as Argo CD or Flux need cluster-wide permissions and cannot be installed.
  • Resources: CPU, memory and storage are shared between all students; there is no fixed quota per namespace. Keep resource requests small and delete what you no longer use, so everyone can work.
Security: other students can read the resources in your namespace, including pod specifications and environment variables. Never put company code, data, model weights or credentials on the cluster. Keep passwords and tokens in Kubernetes Secrets (referenced with secretKeyRef), never as plain environment values or in ConfigMaps.

1. Install the Tools

OS kubectl Helm
macOS (Homebrew) brew install kubectl brew install helm
Windows (scoop, recommended) scoop install kubectl scoop install helm
Windows (winget) winget install -e --id Kubernetes.kubectl winget install Helm.Helm
Linux (snap) sudo snap install kubectl --classic sudo snap install helm --classic

Check the installation:

kubectl version --client
helm version

Optional: kubectx (brew install kubectx / scoop install kubectx) makes it easy to switch between several kubeconfigs.

2. Add Your Kubeconfig

kubectl reads its connection and authentication details from ~/.kube/config by default. Save the kubeconfig file you received as ~/.kube/config (or merge it into your existing file if you already use other clusters). 

mkdir -p ~/.kube
cp <your-kubeconfig>.yaml ~/.kube/config

Alternatively, point kubectl to the file for the current terminal session:

export KUBECONFIG=/path/to/<your-kubeconfig>.yaml

On Windows (PowerShell):

mkdir $HOME\.kube -Force
copy <your-kubeconfig>.yaml $HOME\.kube\config
# or, for the current session only:
$env:KUBECONFIG = "C:\path\to\<your-kubeconfig>.yaml"

3. Connect and Test

To reach the cluster you must be connected to eduroam, logged in with your Aalborg University student account. Test your configuration:

kubectl get nodes
kubectl get pods

The first command should list the cluster's nodes, and the second should report that no resources were found in your namespace. If you get an error, check that you are on eduroam with your Aalborg University student account and that your kubeconfig is in place.

Off campus: connect through the university VPN, then use kubectl as usual. If you cannot reach the course cluster, most exercises also run on a local Kubernetes cluster on your laptop (e.g. kind, which runs on Docker).

Key Concepts

Kubernetes is a production-grade, open-source platform that orchestrates the placement (scheduling) and execution of application containers within and across computer clusters.

Cluster and Nodes

A cluster consists of a control plane that coordinates all activities, and one or more nodes – worker machines that run your applications. Each node is managed by the control plane and can host many pods.

Deployments and Pods

A Deployment is the recipe for running your application: which container image, how many replicas, which configuration. The control plane continuously keeps the actual state equal to the desired state and replaces pods that fail (self-healing). A Pod is the smallest deployable unit: a logical host for one or more containers that share storage and network. Pods are short-lived, and their IP addresses change when they are rescheduled.

Services, Labels and Selectors

A Service gives a set of pods a stable name and address, providing load balancing and service discovery. It finds its pods through labels (key-value pairs on resources) and selectors. Service types: ClusterIP (default, reachable only inside the cluster), NodePort, LoadBalancer and ExternalName. On the course cluster, use ClusterIP and reach your service with kubectl port-forward. Inside your namespace, a service is reachable by its name, e.g. http://my-service:8080.

Helm

Helm is a package manager for Kubernetes. A chart is a package of Kubernetes resources that you configure through values. An installed chart is called a release.

Warm-up Exercise: Hello Kubernetes

Use this exercise to get familiar with the cluster before the reference project. Download the files first:

  • hello-kubernetes.yaml – a manifest with a Deployment and a Service.
  • hello-kubernetes-1.0.0.tgz – the same application packaged as a Helm chart (default values: values.yaml).

Deploy with kubectl

  1. Inspect hello-kubernetes.yaml. Identify the two resources (separated by ---), the labels and selectors, and how the environment variables are injected with fieldRef (metadata.namespace, metadata.name, spec.nodeName).
  2. Deploy it and list what was created: 
    kubectl apply -f hello-kubernetes.yaml
kubectl get pods
kubectl get services
  3. Connect through the service and open http://localhost:8080 in your browser. Refresh a few times: the page shows which pod, namespace and node handled your request. 
    kubectl port-forward svc/hello-kubernetes 8080:8080
  4. Scale the deployment to 5 replicas, check that there are 5 pods and the application still works, then scale back to 3: 
    kubectl scale deployment/hello-kubernetes --replicas=5
kubectl get pods
kubectl scale deployment/hello-kubernetes --replicas=3

Work inside the cluster

  1. Open a shell in one of the pods, look around (it is a Node.js application; try cat server.js), and exit: 
    kubectl exec -it pods/<name-of-pod> -- /bin/sh
  2. Start a temporary BusyBox pod and call the service from inside the cluster, without port-forwarding: 
    kubectl run busybox --rm -it --image busybox -- sh
wget -qO- hello-kubernetes:8080
    Ask a classmate for their namespace and try wget -qO- -T 5 hello-kubernetes.<their-namespace>:8080 – services in other namespaces are not reachable, so the request times out. Note that you cannot install packages inside a running pod (e.g. apt install), because pods have no internet access.
  3. Start an Ubuntu pod that is not removed when you exit, copy a local file into it, then reattach and check that the file is there: 
    kubectl run ubuntu -it --image ubuntu -- bash
kubectl cp README.md ubuntu:/README.md
kubectl attach ubuntu -c ubuntu -i -t

Deploy with Helm

  1. Install the chart as a release, using a ClusterIP service: 
    helm install hello-kubernetes-helm ./hello-kubernetes-1.0.0.tgz --set service.type=ClusterIP
helm status hello-kubernetes-helm
kubectl get pods,services
    The chart creates 2 pods and a service named hello-kubernetes-hello-kubernetes-helm on port 80. Connect with kubectl port-forward svc/hello-kubernetes-hello-kubernetes-helm 8081:80.
  2. Change the configuration of the release through its values and check that the number of pods changes: 
    helm upgrade hello-kubernetes-helm ./hello-kubernetes-1.0.0.tgz \
  --set service.type=ClusterIP --set deployment.replicaCount=5
helm list

Clean up

kubectl delete -f hello-kubernetes.yaml
helm uninstall hello-kubernetes-helm
kubectl delete pod ubuntu
kubectl get all

Good Practice

  • The cluster is shared: set resource requests/limits and delete what you no longer use (kubectl get all shows what is running).
  • Build all dependencies into your container images. Pods have no internet access, so pip install or apt install at runtime will fail.
  • Keep your manifests and Helm values in Git – never secrets or your kubeconfig.
  • When a pod does not start, check kubectl describe pod, kubectl get events and kubectl logs before asking for help.

Troubleshooting

Symptom Likely cause
ImagePullBackOffWrong image name or tag, or the image is private (GitHub Container Registry packages are private by default). Public registries may also rate-limit pulls; retry later.
exec format errorThe image was built for ARM (e.g. on an Apple Silicon Mac). Rebuild with docker buildx build --platform linux/amd64.
CrashLoopBackOffThe container starts and exits. Read kubectl logs <pod> --previous; often a missing file, a missing environment variable, or a download that needs internet access.
Pod stays PendingNot enough free CPU or memory on the shared cluster (lower your requests, or delete what you no longer use), or a volume that cannot be bound. See kubectl describe pod.
Service names stop resolvingA NetworkPolicy blocks DNS. Allow egress on port 53 to the cluster DNS.
Port-forward works for HTTP but not for KafkaThe broker advertises its in-cluster address. Run clients as pods in your namespace.
