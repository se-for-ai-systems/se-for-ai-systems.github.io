Glossary

Short explanations of terms used in the course

Course Format

Term Meaning
Reference projectThe shared example system (HydraWatch) that you build step by step during the course before applying each step to your own case.
Portfolio assignmentOne of three hand-ins on your own case (P1–P3); revised, they form your exam report.

Software Architecture

Term Meaning
Quality attributeA measurable property a system must have besides its function, e.g. performance, availability, security, modifiability.
Quality-attribute scenarioA testable requirement in six parts: source, stimulus, environment, artefact, response, response measure.
C4 modelA way to draw architecture at four zoom levels: context, containers, components, code.
ADR (architecture decision record)A short document recording one design decision: context, options considered, decision, consequences.
Technical debtShortcuts that make a system faster to build now but more expensive to change later; in ML systems often hidden in data dependencies and glue code.

Infrastructure

Term Meaning
Container / imageAn image packages an application with everything it needs to run; a container is a running instance of an image.
Container registryA server that stores images, e.g. Docker Hub or GitHub Container Registry.
KubernetesA platform that runs and manages containers across a cluster of machines.
NamespaceYour isolated part of the course cluster.
Pod, Deployment, ServiceA pod runs one or more containers; a deployment keeps a number of pods running; a service gives them a stable name and address. See the Kubernetes Cluster Guide.
ConfigMap / SecretKubernetes objects holding configuration and sensitive values (passwords, tokens) for your pods.
NetworkPolicyA rule that controls which pods may talk to which.
Helm chartA package of Kubernetes manifests, configured through values.
Cloud continuumThe range of places where computation can run, from devices at the edge through on-premises servers to public cloud.
EdgeComputation close to where data is produced, e.g. a gateway at a machine.
Data sovereigntyThe requirement that data stays under a given jurisdiction or owner, e.g. on the customer's premises or in the EU.

MLOps and Delivery

Term Meaning
CI/CDContinuous integration (automatically test and build every change) and continuous delivery (keep every change deployable).
GitOpsGit holds the desired state of the system, and an agent in the cluster pulls and applies it continuously. On the course cluster you use push-based deployment from Git instead.
Push-based deploymentYou (or a script) apply the state committed in Git to the cluster, e.g. with helm upgrade --install.
Experiment tracking / model registryRecording training runs (parameters, metrics, artifacts) and storing approved model versions, e.g. with MLflow.
Data versioningRecording which version of the data a model was trained on, e.g. with DVC.
Evaluation gateA CI step that stops a model from being released if it scores below a threshold.
Shadow / canary deploymentRunning a new model next to the old one without using its output (shadow), or on a small share of traffic (canary), before switching.

Data and Monitoring

Term Meaning
Batch vs. stream processingProcessing data in large chunks at intervals, or continuously as each event arrives.
Topic (Kafka)A named, ordered log of events that producers write to and consumers read from.
Feature storeA system that stores model input features so training and serving use the same values.
Training-serving skewFeatures computed differently in training and in production, so the model sees different data than it learned from.
Data drift / concept driftThe input data changes (data drift), or the relation between input and correct answer changes (concept drift).
Proxy metricA signal watched while true labels are not yet available, e.g. the distribution of predictions.
SLI / SLOService level indicator (a measured value, e.g. latency) and service level objective (its target, e.g. 99% of requests under 200 ms).
ObservabilityBeing able to understand a system's internal state from its outputs: metrics, logs and traces.

Knowledge Graphs

Term Meaning
Knowledge graphData organised as entities (nodes) and their relations (edges), with a schema that gives them meaning.
OntologyThe schema of a knowledge graph: the classes of things and the relations allowed between them.
Lineage / provenanceThe record of where data and models come from: which data trained which model, and where it is deployed.

Regulation

Term Meaning
GDPREU General Data Protection Regulation, governing personal data.
NIS2EU directive on cybersecurity requirements for essential and important entities.
EU AI ActRegulation (EU) 2024/1689. Sorts AI systems by risk (prohibited, high-risk, limited, minimal) with obligations that grow with the risk.
