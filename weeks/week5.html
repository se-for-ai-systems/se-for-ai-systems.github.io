Week 5 – Big Data & Data Science Technologies

Portfolio 2 due Monday 22 February 2027 · peer review due Wednesday 24 February
Seminar 3 - Friday 26 February 2027, 09:00–16:00, SDU Odense, room U165

Learning Goals

  • Compare batch and stream processing for AI systems.
  • Design event-driven pipelines and explain core Kafka concepts (topics, partitions, consumer groups).
  • Describe storage technologies for historical and event data (data lake, warehouse, lakehouse, feature store).
  • Validate data in a pipeline and avoid training-serving skew.
  • Discuss data governance, privacy, fairness and the regulations that apply (GDPR, NIS2, EU AI Act).

Exercises

  • Before the seminar: Peer-review two Portfolio 2 submissions (see Portfolio & Exam).
  • Core – Reference project: Deploy a single-node event broker (e.g. Kafka or Redpanda) in your namespace and write a producer that replays the dataset as incoming events. Run producer and consumer as pods in the namespace, not on your laptop.
  • Core – Reference project: Write a consumer that validates events (schema, value ranges), computes features with the same code as training, calls the model service, and publishes predictions to an output topic.
  • Stretch – Reference project: Batch features and predictions to Parquet files in object storage in your namespace, as history for retraining and drift analysis.
  • Own case: Draw the data flow of your system: sources, volume and rate, batch vs. streaming, storage, data ownership and the regulations that apply. Start Portfolio 3.

Notes

A Kafka-compatible broker advertises its in-cluster address, so clients on your laptop behind kubectl port-forward usually fail to connect – run clients as pods. Run the broker as a single node in development mode without operators or cert-manager. If your case uses an LLM: pods have no internet, so use a small open model packaged in the image, and evaluate it with a fixed evaluation set.
