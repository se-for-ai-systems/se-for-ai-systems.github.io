Week 1 – SE for AI Systems & Software Architecture

Seminar 1 - Friday 29 January 2027, 09:00–16:00, SDU Odense, room U162
Before the seminar: complete the checklist below, read the required literature and prepare a 3-minute pitch of a problem from your company.

Before Week 1

  • A laptop where you have admin rights (company laptops often block the tools below).
  • Install Python 3.11 or newer, Git, Docker Desktop or Podman, kubectl and Helm (install commands in the Kubernetes Cluster Guide).
  • Create a GitHub account and a container-registry account (Docker Hub or GitHub Container Registry).
  • Activate your Aalborg University student account and eduroam access. Your personal kubeconfig is sent to you by email before the course starts; add it as described in the Kubernetes Cluster Guide.
  • Get the two course books (Bass et al. and Huyen), see Course Books.
  • Do the warm-up exercise in the Kubernetes Cluster Guide.
  • Prepare your case pitch; read Your Case first (a sanitised pitch is fine).

Learning Goals

  • Explain how AI systems differ from traditional software systems and describe the AI system lifecycle.
  • Identify sources of technical debt in ML systems.
  • Use a shared architecture vocabulary: quality attributes, architectural views, tactics and design decisions.
  • Formulate a problem from your own company as the basis for the portfolio.

Literature

  • Required: [Bass et al., 2025] Engineering AI Systems. Ch. 1 (Introduction: terminology, system quality, lifecycle and processes, software architecture, AI model quality, dealing with uncertainty).
  • Required: [Sculley et al., 2015] Hidden Technical Debt in Machine Learning Systems. NeurIPS 2015.
  • Required: [Menzies, 2020] The Five Laws of SE for AI. IEEE Software 37(1).
  • Optional: [Huyen, 2022] Designing Machine Learning Systems. Ch. 1 (Overview of ML Systems).

Exercises

  • Before the seminar: Read the required literature and write down two questions or claims you want to discuss.
  • Before the seminar: Prepare a 3-minute pitch of a problem from your company: context, users, available data, why ML is needed, and the constraint that matters most. No company names are needed.
  • Before the seminar: Set up cluster access and do the warm-up exercise in the Kubernetes Cluster Guide.
  • Reference project: Run the baseline notebook. Using Sculley et al.'s figure as a checklist, list what is missing before the model could run in production.
  • Own case: Start Portfolio 1. Identify stakeholders and draft the first quality-attribute scenarios.
