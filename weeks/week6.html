Week 6 – Observability & Feedback Loops

Self-study week - reading, slides and exercises.
Portfolio 3 due Wednesday 3 March 2027 · peer review due Friday 5 March
Portfolio 3 requires the observability design; dashboards and drift evidence from this week may be added in the final report.

Learning Goals

  • Explain metrics, logs and traces, and what is specific about monitoring ML systems.
  • Detect data and concept drift and monitor model performance in production, using proxy metrics while labels arrive late.
  • Define SLIs and SLOs and set up dashboards and alerts for Site Reliability Engineering teams, keeping service health and model quality apart.
  • Design feedback loops that trigger retraining, rollback or runtime reconfiguration.

Exercises

  • Core – Reference project: Deploy Prometheus and Grafana in your namespace and instrument the FastAPI service (request rate, latency, errors, prediction distribution).
  • Core – Reference project: Add drift detection on the streaming data (compare live features with the training data), inject drift by replaying degraded cycles, and visualize it in a dashboard.
  • Core – Reference project: Define a service SLO (e.g. latency) and a separate model-quality signal (drift or a proxy metric), each with an alert rule. When the model-quality alert fires, roll back to the previous model version (move the registry alias, or revert the commit in Git and redeploy from your laptop).
  • Stretch – Reference project: Run a new model version in shadow mode next to the current one and compare their predictions before switching.
  • Own case: Design the observability and feedback loop for your system. Finish and submit Portfolio 3.

Notes

Install Prometheus and Grafana namespace-scoped: no operator-based stacks, no ClusterRoles (disable RBAC creation, node exporters and cluster-wide metrics), static scrape targets for your own services, and Grafana dashboards provisioned from a ConfigMap. Alerts cannot be sent out of the cluster; view them in the Prometheus and Grafana UIs through kubectl port-forward.
