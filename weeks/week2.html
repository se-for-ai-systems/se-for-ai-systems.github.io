Week 2 – Architecting AI Systems: From Notebook to Code

Self-study week - reading, slides and exercises.
Portfolio 1 due Monday 8 February 2027.

Learning Goals

  • Describe the AI system lifecycle: design, non-AI modules, build, test, release and deploy.
  • Compare distributed architecture styles (client-server, SOA, microservices) and interface styles (REST, GraphQL, gRPC) for AI systems.
  • Specify quality-attribute scenarios for an AI system (e.g. reliability, performance, modifiability).
  • Document an architecture with C4 diagrams and architecture decision records (ADRs).
  • Restructure notebook code into a tested, containerized service.

Literature

  • Required: [Bass et al., 2025] Engineering AI Systems. Ch. 2 (Software Engineering Background), sections on distributed software architectures and interface styles.
  • Required: [Bass et al., 2025] Engineering AI Systems. Ch. 6 (System Life Cycle).
  • Required: [Huyen, 2022] Designing Machine Learning Systems. Ch. 2 (Introduction to ML Systems Design).
  • Optional: [Bass et al., 2025] Ch. 3 (AI Background) – a recap of model selection and hyperparameters from your previous module.
  • Required if your case uses an LLM or other foundation model: [Bass et al., 2025] Ch. 4 (Foundation Models) – customizing FMs and designing systems around them.
  • Optional: [Bass, Clements & Kazman, 2021] Software Architecture in Practice. Quality-attribute scenarios and tactics.
  • Optional: [Brown] The C4 model. [Nygard, 2011] Documenting Architecture Decisions.
  • Optional: [EU, 2024] Regulation (EU) 2024/1689 (AI Act), Art. 5, Art. 6 and Annex III – needed for the risk classification in Portfolio 1.

Exercises

  • Reference project: Refactor the notebook into a Python package (src/ layout, pyproject.toml) with separate data, training and inference modules.
  • Reference project: Add unit tests (pytest) for preprocessing and the model's input/output contract, and evaluate the model per component class, not only overall. Split the data by time or block, not randomly: the dataset comes from a single test rig.
  • Reference project: Serve the model with FastAPI (/predict and /health), write a Dockerfile (start from a slim Python image with CPU-only libraries), and build and run the image locally.
  • Own case: Write 3–5 quality-attribute scenarios (at least one about model quality), draw C4 context and container diagrams, write at least two ADRs, and classify the system under the EU AI Act. Finish and submit Portfolio 1.
